# Decimal calculator

Local-only Circuit Explorer design, generated by `scripts/build-calculator.cjs`.

## Operator flow

1. Enter up to four decimal digits on the 0–9 keypad. New digits shift older digits left; excess digits fall off.
2. Set Variable 1 captures all four digits, then clears the entry in four clocked zero shifts.
3. Enter and set Variable 2 the same way. Each variable has its own four-digit display.
4. Select addition, subtraction or multiplication, then Calculate. The eight-digit answer holds its previous value until the new answer is ready.

Leading zeros remain visible. Subtraction is Variable 1 minus Variable 2, with a minus sign in the leftmost result position when needed. Products reach 99,980,001. Both variables must be explicitly set, including zero. The wired Busy signal protects all transfers and calculations; multiplication takes about 13 simulated seconds.

## Implementation

- 1,155 ordinary editable components and 2,605 explicit wires, plus normal converter/display socket contacts.
- Four Buffer 4 boards store the entry's four BCD bit planes. Two banks of Buffer 1 cells hold the variables independently.
- Ordinary adders convert each stored BCD number to binary. Addition and sign/magnitude subtraction are combinational.
- Multiplication uses fourteen capture/commit rounds with separate main/shadow registers. No live arithmetic feedback is written through an active clock.
- Twenty-eight stored answer bits feed an Add 3 double-dabble conversion network and eight seven-segment converters. Ordinary gates select the minus glyph on the leftmost display's seven segment inputs.
- JavaScript only serializes source button pulses and reads the circuit's Busy/Ready outputs for button availability. It does not calculate, assign operand/result bits, or force wires on.
- Reset inputs and sessionless imports/copies cancel six transient command/edge-memory cells. They preserve entry, operands, operation, validity and result memory. A valid in-memory project timing session resumes its clock phase.

## Verification

The arithmetic and logical-control suites cover zero and maximum operands, signed subtraction, all fourteen multiplication rounds, capture-before-clear, independent variable displays, repeated commands, Busy interlocks and pause behavior. Physical routing is checked separately against the generator's intended connections; numerical correctness alone is not sufficient to rule out shorts.

The baked graph passes an exact comparison of 1,606 physical nets and 4,966 sockets. All 13,813 wire segments pass board-clearance and separate-parallel-lane checks. Only a display/converter's own first or last face-contact lead may enter that component; other boards remain protected.

The full physical-network test enters operands through ordinary button presses and checks `12 + 3 = 15`, `3 − 12 = −9`, and `12 × 3 = 36`. Disconnecting the answer bus leaves the stored answer at 36 but makes the decimal display show zero, proving the displayed result follows real wiring.

A separate localhost browser project also passed entry/capture/clearing, `12 + 3 = 15`, then `12 × 3 = 36`, with Busy disabling the controls during multiplication and no captured browser errors. Existing projects on 127.0.0.1 were not changed.

Final regression run: all 296 tests passed with `node --test --test-isolation=none --test-reporter=dot tests/*.test.cjs`. The two application JavaScript assets are hash-identical and the generated routing worker matches the tested source. JavaScript syntax checks pass.

The forwarded-memory contact optimization retains exact half-unit socket tolerance, source-node exclusions and target order, with dedicated regression tests. It caches geometry with topology rather than repeating a full socket scan for every memory pulse and gate pass.

This is simulator verification, not a claim of measured in-game timing parity. No production deployment is part of this update.
